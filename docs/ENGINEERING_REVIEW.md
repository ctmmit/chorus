## Resolved open questions

### Q1 — Audio engine: `podcast-creator` + ElevenLabs via `esperanto`

Chorus stays a thin agent-native FastAPI service and `pip install
podcast-creator` for the podcast engine (the standalone library extracted
from Open Notebook, by lfnovo, MIT). TTS runs through `esperanto` (a
LiteLLM-style provider abstraction) with **ElevenLabs** as the provider.

- Authorship preserved: podcast-creator is **script-controlled** (the agent
  authors the opinionated script; the library does not auto-write it like
  NotebookLM). This is the thesis.
- Episode Profiles map onto the `soul` (speaker/persona config).
- 1-4 speakers from one library: spine floor = single-voice monologue;
  two-host layer = same library, more speakers.
- `esperanto` makes TTS provider-swappable (ElevenLabs for quality, Edge/
  OpenAI for cost) with no code change.
- Rejected: forking full Open Notebook (SurrealDB + Next.js = innovation
  token + human-notebook data model, fights agent-native thesis);
  NotebookLM (Enterprise-only API, loses authorship); ElevenLabs-direct
  (rebuilds the outline→script→audio orchestration the library gives free).
- Watch item: podcast-creator is less battle-tested than open-notebook
  itself. Mitigation: esperanto abstracts the TTS, and the spine floor
  (single-voice) is reachable via a direct TTS call if the library slips.

### Q2 — Transcripts: managed API + YouTube URLs + pre-transcribed fixtures

Keep the §6 YouTube-URL input. For the live path, call a **managed
transcript API** (Supadata or TranscriptAPI) that runs extraction on its
own infrastructure — a REST call from the service, no residential-proxy
maintenance. `youtube-transcript-api` direct is confirmed IP-blocked from
datacenter ranges in 2026, so it is out.

- `path_test.sh` runs against **pre-transcribed fixtures** checked into
  `/fixtures` — tests never depend on a live third party.
- Specified failure case (§6): a missing/removed video or a transcript-API
  failure for one episode → skip it, log a structured reason, complete the
  digest on the rest.
- Pick Supadata vs TranscriptAPI during Goal 1 on price + word-level
  timestamp quality (timestamps must be granular enough for citation
  resolution). Both are REST; the adapter is one module behind an interface.

### Q3 — Request lifecycle: fully async, one poll endpoint

```
POST /digest  { soul, context, episodes[], highlight_count? }  → { job_id }
GET  /digest/{job_id} → { status, ... }
        status: queued → digest_ready → done | failed
        digest_ready: digest[] present, audio_url null   (≤ 90s)
        done:         audio_url present                  (≤ 5 min)
        failed:       error{} with structured reason
```

One mechanism, progressive states. Avoids the sync-HTTP timeout risk of
holding ~10 live transcript fetches + LLM calls in one request. Latency
bounds become `path_test` assertions: **digest ≤ 90s, audio ≤ 5 min**
(against pre-transcribed fixtures the digest will be far faster; 90s is a
safe ceiling that includes live fetch in production).

### Q4 — Charts data source (Layer 3, post-July-11): Podcast Index API

When taste presets ship, use the **Podcast Index API** (free, API-key,
server-side friendly, open). Apple/Spotify charts are unofficial/scraped
and hostile to server-side use. Deferred past the finale per DESIGN_DOC.

### Q5 — Soul-version provenance: content hash + version on every digest

Each digest output records `soul_version` = a short content hash of the
`soul.md` used (plus an optional caller-supplied label). Cheap, makes the
"which lens produced this" auditable, and is the hook the Layer-1
agent-interview needs when the soul changes across calls.

## Architecture — data flow

```
                        ┌─────────────────────────────────────────┐
  caller (agent)        │              CHORUS SERVICE               │
  ──────────────        │                                          │
  POST /digest ─────────┼─→ validate (Pydantic) ─→ create job ─────┼─→ jobs (SQLite)
   {soul,context,       │        │                                 │      status=queued
    episodes[]}         │        └─→ BackgroundTask ───────────┐   │
                        │                                       │   │
  GET /digest/{id} ←────┼── read job status ←───────────────┐  │   │
                        │                                    │  ▼   │
                        │   ┌────────────── pipeline ────────┴──────┴────┐
                        │   │ 1. transcripts: managed API (parallel)     │
                        │   │      └ skip+log on miss (failure case)     │
                        │   │ 2. segment scoring: Haiku f(seg,soul,ctx)  │
                        │   │      → {score, reason, citation}           │
                        │   │ 3. below-threshold → "nothing cleared bar" │
                        │   │ 4. digest assembled → status=digest_ready  │  ≤90s
                        │   │ 5. script synth: Sonnet (POV, traceable)   │
                        │   │ 6. podcast-creator + ElevenLabs → audio    │  ≤5min
                        │   │ 7. audio_url stored → status=done          │
                        │   └────────────────────────────────────────────┘
                        └──────────────────────────────────────────┘
```

## Job lifecycle — state machine

```
   POST                pipeline 1-4         pipeline 5-7
  ──────►  queued ────────────────► digest_ready ────────────────► done
              │                          │                          ▲
              │ any fatal error          │ audio render fails       │
              └──────────► failed ◄──────┴──────────────────────────┘
   (a single episode failing is NOT fatal: skip+log, continue — §6)
```

## Failure modes (each new codepath, one realistic production failure)

| Codepath | Failure | Test? | Error handling | User sees |
|---|---|---|---|---|
| Transcript fetch | API down / video removed | fixture: missing-transcript | skip+log, continue | digest on remaining eps |
| Transcript fetch | all episodes fail | **GAP — add test** | must return failed w/ reason | clear failure, not empty success |
| Segment scoring | LLM timeout/429 | unit (mock 429) | retry w/ backoff, then skip seg | partial digest + logged gap |
| Citation resolve | timestamp not in transcript | fixture assertion | drop highlight, don't fabricate | fewer highlights, never wrong ones |
| Below-threshold | all segments low | ungrounded fixture | explicit "nothing cleared bar" | honest refusal |
| Script synth | claim not traceable | unit (assert traceability) | regenerate or drop claim | no ungrounded takes |
| Audio render | ElevenLabs error/quota | unit (mock fail) | status=done w/ audio_url=null + note | digest + "audio unavailable" |
| Job poll | unknown job_id | unit | 404 | clear error |

**Critical gap flagged:** "all transcripts fail → must return `failed`, not
an empty `done`." Silent empty success is the worst outcome for a cold
agent. Goal 1 must include this test.

## Risks + mitigations

1. **podcast-creator maturity** (med). Mitigate: esperanto abstracts TTS;
   single-voice spine floor reachable via direct ElevenLabs call if needed.
2. **Managed transcript timestamp granularity** (med) — citation resolution
   needs word/segment-level timestamps. Mitigate: validate during Goal 1
   provider pick; fixtures are pre-transcribed with known-good timestamps.
3. **Curation taste is subjective** (med). Mitigate: path_test asserts
   structure + citation + refusal, never taste; Goal 5 two-soul eval makes
   the lens visible. Taste is demoed, not unit-tested.
4. **Paid-API cost during loops** (low). Mitigate: Haiku for per-segment;
   cache transcripts + scores; AUTOPILOT $25/session, $75/day caps.
